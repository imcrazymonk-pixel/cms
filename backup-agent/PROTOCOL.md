# Backup Agent Protocol v1

Agent ↔ CMS contract. Base path: `/api/backup-agent/v1`.

## Authentication

Every request (except `install.sh`) carries:

```
Authorization: Bearer <AGENT_TOKEN>
X-Agent-Version: 0.1.0
X-Agent-Protocol: 1
```

The CMS stores only `encrypt(token)` in `backup_agents.token_enc`. A leaked CMS
database alone does not expose the token (it is encrypted with the CMS key).

## Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/install.sh` | installer script (public) |
| POST | `/register` | first contact: `{host_id, token, agent_version, protocol_version}` |
| POST | `/heartbeat` | every 30 s: `{agent_version, spool_bytes, disk_free, uptime_seconds}` |
| GET | `/state` | desired state (recipes, components, policies/tiers); supports `If-None-Match` → `304` |
| POST | `/inventory` | containers/ports/disk; CMS matches recipes and upserts components |
| POST | `/runs` | create a run from the agent side; `client_run_id` makes it idempotent |
| PATCH | `/runs/{id}` | progress, steps, log tail, status, error; response contains `cancel_requested` |
| POST | `/runs/{id}/artifacts` | register an artifact; response contains `upload_url` |
| PUT | `/upload/{artifact_id}` | stream bytes; CMS verifies sha256 and rejects mismatches |
| GET | `/download/{artifact_id}` | stream artifact back (restore) |
| GET | `/commands?limit=10` | take queued commands (`scan`, `backup_now`, `restore`, `cancel`, `update`) |
| POST | `/commands/{id}/finish` | `{status: done|failed}` |

## Invariants

1. **Idempotency** — `client_run_id` is a UUID generated by the agent. Repeating
   `POST /runs` with the same id returns the existing run.
2. **Artifacts** — the agent always sends `sha256`; the CMS recomputes it during
   upload and deletes the object on mismatch.
3. **Offline mode** — if the CMS is unreachable the agent:
   - keeps executing the cached schedule;
   - writes artifacts to the spool;
   - uploads them later and only then deletes the local copy.
4. **Cancellation** — the agent checks `cancel_requested` in every `PATCH` response
   and aborts between steps.
5. **Versioning** — `desired_version` comes from `/state` and `/heartbeat`.
   The agent only reports a mismatch; image update is a deploy operation.
6. **Secrets** — env values of containers are never sent. `/inventory` reports
   only env **keys**.

## Error codes

| Code | Meaning | Agent behaviour |
|------|---------|-----------------|
| 401 | invalid/rotated token | log, retry with backoff, do not drop spool |
| 404 | run/host not found | mark command failed |
| 409 | conflict (state) | refresh state and retry next tick |
| 5xx | CMS failure | retry up to 3 times, then keep working offline |
