# Настройка экономии токенов в KiloCode (VS Code)

Сделано:
1. `.kilocodeignore` – исключает node_modules, dist, lock‑файлы, логи, медиа и большие дампы.
2. `CONTEXT.md` – выжимое описание стека, соглашений и команд.
3. `STRUCTURE.md` – дерево каталогов без исходного кода.
4. `MEMORY.md` – файл активной задачи (обновлять в конце каждой сессии).
5. Обновлён `kilo.json`:
   - добавлен блок `permission.read` с запретом чтения мусора.
   - оставлены `skillsAlways` и пустой `skills` block (совместимо с текущей схемой).

Далее в настройках KiloCode (или Roo Code / Cline) создайте три Custom Mode:
- **Architect** – модель DeepSeek, системный промпт включает `@CONTEXT.md @STRUCTURE.md` и инструкцию: «Ты работаешь в режиме Tech Lead. Твоя задача — архитектурное планирование и аудит diff. Не генерируй тривиальный бойлерплейт, если об этом явно не попросили. Формулируй требования к коду емко, строго типизировано, с акцентом на edge cases».
- **Executor** – модель DeepSeek‑V3 / Sonnet‑3.5 или локальная Ollama (qwen2.5‑coder:14b), без ограничений на чтение (игнор‑файл уже отфильтровал мусор).
- **Reviewer** – модель DeepSeek, системный промпт: «Прими только git diff и вывод тестов, дай точечный вердикт: approve или список правок (без переписывания кода полностью).»

Рабочий цикл:
1. Новый чат → Architect → попросите план → сохраните в `TASK.md`.
2. Переключитесь на Executor → дайте `@TASK.md @CONTEXT.md @STRUCTURE.md` и явные `@src/...` файлы → реализуйте + напишите тесты.
3. Выполните в терминале: `git diff main > changes.diff` и `npm test > test.log 2>&1` (или `pytest`).
4. Новый чат →Reviewer → передайте `changes.diff`, `test.log`, `@TASK.md` → получите ревью и при необходимости правьте.

Эта схема сокращает расход дорогих моделей до нескольких тысяч токенов за сессию, позволяя использовать миллионы токенов флагмана на месяцы разработки.
