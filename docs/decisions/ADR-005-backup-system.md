# ADR-005. Подсистема бэкапов и аварийного восстановления

- **Статус:** принято
- **Дата:** 2026-11-21
- **Связано:** `docs/plans/2026-11-21-backup-system.md`, ADR-002 (структурный паритет с Remnawave)

## Контекст

Инфраструктура распределена: CMS живёт на `85.198.99.102`, а Remnawave Panel,
Bedolaga Bot, Cabinet и ноды — на других серверах (`144.31.156.172` и ноды).
Ручные `pg_dump` + cron из `DEPLOY.md` покрывают только БД CMS, не учитывают
связность «панель ↔ бот» (`remnawave_uuid`, `squad_uuid`), не имеют манифеста
версий и не позволяют развернуть копию на новом сервере.

Готовые решения (`distillium/remnawave-backup-restore`, PEDZEO, Chivas600,
remnatools) закрывают отдельные сервисы, но не дают единого согласованного
среза и управления из CMS.

## Решение

### 1. Агент-первый (agent-first), CMS — оркестратор

На каждом сервере работает `backup-agent` (Python 3.12 в Docker). CMS:

- хранит рецепты, политики, уровни, хранилища и манифесты;
- планирует запуски и кладёт команды в `backup_commands`;
- принимает артефакты и раскладывает их по хранилищам.

Агент имеет **локальное расписание** и spool: если CMS недоступна, бэкапы
продолжаются, артефакты копятся и досылаются позже. Вариант «всё по SSH из
FastAPI» используется только для bootstrap агента и аварийных операций.

### 2. Модульность — вариант A

Подсистема оформлена как вертикальный срез по образцу `support/` и `bedolaga/`:
`api/v1/backups/`, `api/v1/backup_agent.py`, `core/backup/`, `schemas/backup.py`,
`pages/backups/`, `backup-agent/`. Проводка — 4 статические точки
(`main.py`, `navigation.ts`, `App.tsx`, `integrations.py`). Runtime-реестра
модулей нет (см. ADR-002: `plugins/` в CMS отсутствует).

### 3. Хранилища — данные, а не настройки

Бесконечный список хранилищ хранится в `backup_storages`, а не в `settings`:
статический `SettingDef` не поддерживает список объектов, а JSON-блоб в
`settings` не шифрует секреты (`settings.py` шифрует только `is_secret`).
Секреты — отдельная колонка, зашифрованная `core/crypto.py` (AES-256-CBC).

Типы: `local`, `s3`, `sftp`, `ssh`, `webdav`, `ftp`, `rclone`. WebDAV/FTP
реализуются через rclone-remote, чтобы не тащить отдельные драйверы.

### 4. Уровни (tiers) вместо одной политики

Один хост может иметь несколько уровней: «БД каждый час», «полный раз в
сутки», «месячный архив». У каждого — свой scope, расписание, retention и
набор хранилищ. Retention поддерживает режим `auto` (число копий → дни).

### 5. `quiesce` — только вручную

Плановые уровни всегда `online` (`pg_dump` консистентен без остановки).
Остановка сервиса ради файлового среза выполняется только по явной кнопке:
в момент рестарта может идти оплата или вебхук.

### 6. Шифрование

Артефакты шифруются `age` на агенте (публичный ключ в `/state`). Приватный
ключ хранится в CMS (обёрнут `APP_ENCRYPTION_KEY`) для автоматического
restore и офлайн-копия у владельца. Перед восстановлением — подтверждение в UI.

### 7. CMS бэкапит себя сама

Хост с `transport=inline` исполняется в процессе API (`core/backup/inline.py`):
`pg_dump hexacms` + tar `uploads_data` + манифест. Для такого хоста запрещено
единственное `local`-хранилище: копия обязана уходить offsite.

## Последствия

**Плюсы**

- бэкапы не зависят от доступности CMS;
- согласованный срез панели и бота с проверкой UUID-связей;
- манифест фиксирует digest'ы образов и версии миграций → restore не «лотерея»;
- восстановление на другой сервер тем же агентом;
- всё управляется из UI, без SSH-рутины.

**Минусы / риски**

- агент монтирует `docker.sock` (root-equivalent) — компенсируется non-root
  процессом, ro-монтированиями и отсутствием `privileged`;
- приватный ключ в CMS снижает пользу шифрования при компрометации CMS —
  компенсируется мастер-подтверждением и офлайн-копией;
- inline-исполнитель требует `postgresql-client` и ro-mount uploads в образе `api`.

## Альтернативы

- **Bash-скрипт на каждом хосте без CMS** — отвергнут: нет единого учёта,
  манифестов и UI.
- **Полная плагинная система** — отвергнута: приватная админка, динамический
  импорт кода неоправдан.
- **Единственный `pg_dumpall`** — отвергнут: не покрывает файлы, сертификаты,
  версии и связность сервисов.
