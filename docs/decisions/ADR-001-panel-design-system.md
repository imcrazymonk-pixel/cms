# ADR-001: Дизайн-система админ-панели (remnawave-стиль)

## Status

Accepted

## Date

2026-08-26

## Context

Админ-панель CMS NewWeb имела устаревший визуальный стиль (`admin/css/admin.css`,
шрифт Outfit, светлые карточки). Поставлена задача переоформить её в стиле
remnawave-admin: тёмная тема, mesh-фон, glass-эффекты, акцентные пресеты,
командная палитра, настройки вида (тема/режим/плотность/радиус/шрифт/анимации),
единые таблицы списков.

Жёсткие ограничения проекта: никаких npm/сборщиков (только vanilla CSS/JS/PHP),
не трогать публичную часть (HexaVeil, блог-темы), не менять маршруты/контроллеры/
логику/имена полей форм, файлы не больше 500 строк, не коммитить `Fin/`.

## Decision

Создана собственная дизайн-система панели на чистом CSS/JS/PHP:

- **Токены и темы:** `public/css/panel/{tokens,themes,base,effects,components,table,layout}.css`.
  Цвета — `hsl()`-переменные, 6 акцентных пресетов через `[data-theme]` (Obsidian,
  Halo, Arctic, Sakura, Twilight, Ember) + светлый режим через `[data-mode="light"]`.
- **Настройки вида:** сохраняются в `user_preferences` (таблица + модель +
  эндпоинт `POST admin/settings/save-preference`). Тема/режим — на сервер (рендер
  на `<html>` до JS), остальное — в `localStorage`. Управление — dropdown в шапке
  + `admin/js/panel.js`.
- **Командная палитра:** `admin/js/command-palette.js`, открывается `Ctrl+K`.
- **Единые списки:** `core/DataGrid.php` — рендерер таблиц (все 7 разделов
  переведены на него).
- **Иконки:** `core/helpers_icons.php` — inline Lucide (stroke-based).
- **Без сборщиков:** весь код vanilla, линт через `php -l` (PHP 7.4 из OSP).

### Адаптации к реальному коду

В ходе реализации план (`docs/superpowers/plans/2026-08-26-panel-ui-redesign-plan.md`)
адаптирован к фактическому состоянию кода:

1. **Изоляция веткой, а не worktree.** Open Server Panel отдаёт сайт из основного
   checkout (`C:\OSPanel\home\HexaCMS\public`, домен `http://hexacms`), отдельный
   git-worktree невозможно проверить в браузере без переконфигурации панели.
   Работа выполнена на ветке `feat/panel-redesign`, каждый шаг — отдельный коммит.
2. **Новые ключи иконок.** Добавлены `hexa`, `file-text`, `folder`, `file`, `menu`,
   `image`, `palette` (используются в новом layout и палитре); все старые ключи
   сохранены для обратной совместимости. Исправлен унаследованный баг: `icon()`
   выводил два атрибута `class` (`class="icon" class="icon-lg"`) — теперь
   `class="icon icon-lg"`.
3. **`DataGrid` зарегистрирован в `Autoloader`** (classMap), иначе автозагрузка
   не находит класс в `core/`.
4. **Улучшения `DataGrid`:** URL-плейсхолдеры `{field}` (не только `{id}` — пример
   плана `/post/{slug}` иначе не работает) и опция `confirm` для действий
   (рендерит `data-confirm`, обработчик в `panel.js`).
5. **Категории:** починена сломанная кнопка «Сохранить» — она ссылалась на
   несуществующий атрибут `form="update-cat-X"` и не отправляла форму. Кнопка
   размещена внутри инлайн-формы (поле `name`, маршрут и CSRF не менялись).
6. **Посты:** убраны мёртвые чекбоксы массового выбора и пагинация — контроллер
   не передаёт `$total`/`$page`, bulk-логики нет. Фильтры сохранены.
7. **Layout:** сохранены `$message` (alert-info) и `id="main-content"` (skip-link)
   из прежнего шаблона.
8. **CSRF:** для внутреннего эндпоинта `save-preference` строгая проверка CSRF
   намеренно не применяется (fetch из своего UI, сессия уже проверена
   `Auth::requireAdmin()`, значения — по белому списку ключей).
9. **Дата медиа:** `modified` — unix-таймстамп (`filemtime`), обрабатывается
   `date()` напрямую (не через `format_date()`/`strtotime()`).
10. **Кэш статики:** JS/CSS подключаются с `?v=filemtime(...)`.

## Alternatives Considered

### Tailwind CSS / сборщик (Vite, npm)
- Pros: быстрые утилиты, популярность.
- Cons: нарушает жёсткое ограничение «никаких npm/сборщиков»; усложняет развёртывание
  на Open Server Panel.
- Rejected: проект намеренно vanilla.

### Готовая UI-библиотека (remnawave-admin на React/Next.js)
- Pros: готовые компоненты и стили.
- Cons: конфликт с PHP-архитектурой CMS; потребовал бы переписывания админки.
- Rejected: дизайн-система перенесена концептуально, не кодом.

### Преобразование сетки медиа в карточки (сохранение старой сетки)
- Pros: привычный вид медиа-библиотеки.
- Cons: нарушает требование «все списки через DataGrid»; план явно предписывает таблицу.
- Rejected: медиа переведена на DataGrid-таблицу с колонкой превью.

### Хранение всех настроек вида только в localStorage
- Pros: проще, без миграции БД.
- Cons: настройки темы/режима не переносятся между браузерами и сбрасываются при
  очистке хранилища; план требует per-user сохранения темы/режима.
- Rejected: тема/режим — в БД, остальные настройки — в localStorage (как в плане).

## Consequences

- Единый источник дизайн-токенов в `public/css/panel/`; смена акцента/режима
  без правок шаблонов (через атрибуты `data-theme`/`data-mode`).
- Все списки админки рендерятся единообразно через `DataGrid`.
- Персональные настройки вида (тема/режим) сохраняются в БД за пользователем.
- Новые компоненты панели должны использовать существующие токены/классы и
  оставаться в пределах 500 строк на файл.
- OSP-копия репозитория (`C:\OSPanel\home\HexaCMS\public`) должна синхронизироваться
  с рабочим репозиторием (домен `http://hexacms` отдаёт ту же версию).
- Публичная часть (HexaVeil, блог-темы) и маршруты/контроллеры не изменялись.
